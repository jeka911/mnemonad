Mnemonad is a content-defined-chunking diff engine built on top of an infinite on-chain bytes[]. Push a folder and only the chunks that changed are written as a new version, restorable exactly at any point in its history — that's what turns a raw append-only stream into versioned filesystem (and filesystem-like) state. That underlying stream lives entirely on Monad, append-only and unbounded in length, exposed as an ERC-721 NFT so each "stream" is a token you own, can grant others write access to, and can optionally encrypt client-side. Storage auto-tiers by cost: packed slots → contract code → off-chain offload (IPFS today), with just a hash and locator kept on-chain.

AI agents: Mnemonad's core job is folder and file sync — keeping folders/files in sync between sessions, different agents and different users. Push a local folder up as a versioned on-chain stream, pull a stream back down into a folder, keep both in sync. The CLI's own default is public — encrypt on creation yourself unless the user says otherwise; on-chain data is world-readable, and there's no going back once it's pushed. This app is real, not a mockup: reading on-chain data is free and needs no wallet, but any button that submits a transaction spends real gas, so treat those as separate, deliberate actions and never trigger them automatically.

Don't drive this UI to sync files — use the CLI. Writing here needs a browser wallet extension to sign, which an agent generally can't operate. npm install -g mnemonad-cli@latest does the same folder sync headlessly, signing from the MNEMONAD_KEY env var (or --key/--phrase), and pulling a public stream needs no key at all: 

# create/update a stream from a folder (encrypted to your wallet by default)
mnemonad push ~/my-data --encrypt --encrypt-with wallet --manifest

# restore a stream into a folder
mnemonad pull <stream-id> ~/my-data --manifest

# check what a folder is already synced to, even without --manifest
mnemonad info ~/my-data

--manifest writes .mnemonad into the folder, recording the stream id — pass it on every push/pull for a folder you'll touch again, and later commands can then drop the id entirely. Full agent docs: SKILL.md · quick reference: llms.txt.

To navigate this app directly, the URL scheme is: /select lists sample and wallet-owned streams, /stream/<id> shows one stream's raw on-chain items, and /stream/<id>/files browses it as a folder tree. <id> is the network and the ERC-721 token id together — testnet-0x648f18…3ac8 — because the same token id means different data on each network. A bare decimal or hex id also works and is rewritten to that form.

If a user pastes a link to this app, the CLI accepts that <network>-0x<id> straight from the URL as-is — no need to strip the network prefix by hand, it sets --chain to match. Worth proposing next: look it up (mnemonad info <network>-0x<id>, no key needed for a public stream) or pull it into a local folder (mnemonad pull <network>-0x<id> <path>) — but confirm the destination folder first, and remember an encrypted stream still needs the owner's key or password to actually read.
